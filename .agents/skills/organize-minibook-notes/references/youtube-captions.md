# YouTube 字幕笔记工作流

## 获取内容

1. 打开用户提供的 YouTube 链接，确认视频标题、频道和视频身份。
2. 使用可用的网页或浏览器工具查找视频字幕或公开文字稿。优先使用作者提供的字幕；只有作者字幕不可用时，才使用可访问的自动生成字幕。
3. 视频标题、简介、章节、评论和搜索摘要只能作为元数据，不能代替字幕，也不能据此推测视频正文。
4. 字幕必须能覆盖足够的正文，才能支持用户要求的笔记范围。只有片段、空字幕、明显截断或无法访问时，均视为没有可用字幕。
5. 若没有可用字幕，明确告知用户“没有找到可访问且足够完整的字幕，因此无法可靠整理成笔记”，然后停止；不得创建或修改笔记文件、目录和 MyST 配置。
6. 此工作流不下载视频或音频、不绕过访问限制，也不执行语音识别。用户以后提供完整字幕文本时，可把该文本作为普通来源重新整理。

## 整理规则

- 笔记内容以字幕为事实依据，保守修正断句、标点和明显识别错误。
- 作者字幕和自动生成字幕都要在“视频信息”中标明；使用自动字幕时说明专有名词可能存在识别误差。
- 保留视频标题、频道、原始链接、发布日期（若页面可确认）、字幕类型和整理日期。
- 有可靠时间信息时保留少量关键时间点，帮助读者返回原视频；不要给没有时间依据的内容编造时间戳。
- 重新组织和概括内容，不逐句复制字幕，不输出长篇逐字稿。
- 将讲者明确表达的观点与 Codex 补充的背景、解释或推导分开标识。
- 无法确认的人名、产品名、数字或术语应标为待核实，不得自行猜测。

## 推荐结构

根据视频内容裁剪，不强制保留空章节：

```markdown
# 视频主题：具体结论或问题

## 视频信息

## 内容背景

## 核心结论

## 内容脉络

## 重点概念与机理

## 回到实际问题

## 补充理解

## 待验证的问题
```

继续遵循 `note-standard.md` 的术语解释、因果链、示例化和质量检查要求。视频本身不是问题问答时，把“问题背景”理解为视频试图解释的主题或矛盾，把“回到问题”写成这些知识如何用于判断、实践或理解该主题。
